## Diagnosis

**Root cause:** The pod references an `imagePullSecrets` entry named `c009-missing-pull-secret` that **does not exist** in the namespace.

**Evidence:**
1. The pod's image (`private.invalid.local/team/train:v2`) is from a private registry.
2. The pod spec has `spec.imagePullSecrets[0].name: c009-missing-pull-secret`.
3. `kubectl get secret c009-missing-pull-secret -n siclaw-eval-yye-20260602` returns `NotFound`.
4. kubelet events confirm: `FailedToRetrieveImagePullSecret` — "Unable to retrieve some image pull secrets (`c009-missing-pull-secret`); attempting to pull the image may not succeed."
5. The pod has been in `ImagePullBackOff` for 15 hours, confirming the secret was never created.

**Impact:** The container `main` cannot be started at all. The pod has been stuck in `Pending`/`ImagePullBackOff` since creation (15h ago). This blocks the GPU training workload entirely.

**Confidence:** High — the non-existent secret is the direct and only cause. The image itself likely exists at `private.invalid.local/team/train:v2` (no `ErrImagePull` from the registry), but kubelet cannot authenticate to pull it.

**Safe remediation suggestion:**

Create the missing pull secret with the correct registry credentials:

```bash
kubectl create secret docker-registry c009-missing-pull-secret \
  --namespace siclaw-eval-yye-20260602 \
  --docker-server=private.invalid.local \
  --docker-username=<username> \
  --docker-password=<password> \
  --docker-email=<email>
```

After the secret is created, the pod will automatically retry pulling the image and should proceed to `Running`. No pod restart is needed.
