- The only real GPU-capable nodes (`gpu-10-208-55-159` and `hpe-node144`) each have **8 nvidia.com/gpu** allocatable.

- The remaining nodes are CPU-only, control-plane, `NotReady`, or unschedulable — none carry GPUs.

> `5 Insufficient nvidia.com/gpu` — the only 5 nodes that are otherwise schedulable can't provide even close to 999 GPUs.

| Scheduler events | `5 Insufficient nvidia.com/gpu` out of 368 nodes evaluated |

### Impact / Scope

- **Single pod** `c032-pending` in namespace `siclaw-eval-yye-20260602`. No other resources are affected.

### Confidence

**High** — the 999 GPU request is clearly a misconfiguration (the intended number was likely `1` or `8`).

### Safe Remediation

**Reduce the GPU request** to an amount that matches cluster capacity (max 8 GPUs per node):

```yaml

  limits:
    nvidia.com/gpu: 8   # or 1 if only a single GPU is needed
  requests:
    nvidia.com/gpu: 8   # match limits
```

Alternatively, if the intent is to use all GPUs across multiple nodes (distributed training), the workload should be deployed as a **Volcano Job** or a distributed framework (e.g., PyTorch DDP) rather than a single monolithic Pod requesting 999 GPUs.
