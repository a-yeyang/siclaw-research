```markdown
## Diagnosis: c044-pending — Unschedulable (Node Affinity Mismatch)

The pod has a **required node affinity** rule that no node in the cluster satisfies:

```
requiredDuringSchedulingIgnoredDuringExecution:

        - key: siclaw.ai/nonexistent-affinity

```
The label `siclaw.ai/nonexistent-affinity=true` does **not exist on any** of the 368 nodes in the cluster. The scheduler event confirms this directly:

> `5 node(s) didn't match Pod's node affinity/selector`

1. **Pod spec** — `nodeAffinity.requiredDuringSchedulingIgnoredDuringExecution` with `siclaw.ai/nonexistent-affinity In [true]`
2. **Scheduler event** — `FailedScheduling` explicitly lists "didn't match Pod's node affinity/selector" for 5 nodes
3. **Node label check** — Confirmed zero nodes carry any `siclaw.ai/*` label

### Impact / Scope

- **Only this pod** is affected — no other resources are involved.
- The pod will remain Pending indefinitely under current configuration.

### Confidence: High

The pod spec and scheduler event agree precisely on the cause.

### Remediation

The fix depends on intent:

- **If the affinity is a mistake/misconfiguration**: Remove the `nodeAffinity` block from the pod spec entirely, or correct the label key/value to match an existing node label.
- **If the affinity is intentional but the label is missing**: Add the label `siclaw.ai/nonexistent-affinity=true` to one or more real, schedulable nodes via `kubectl label node <name> siclaw.ai/nonexistent-affinity=true`.

Both fixes require write access, which I cannot perform — a user or CI pipeline should apply the correction.
```
