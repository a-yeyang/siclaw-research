- **Pod status**: `ContainerCreating` / `Pending` for 15 hours — the kubelet cannot proceed because volume setup fails.
- **Kubelet event** (repeat count **453** over 15h):
  ```
  Warning  FailedMount  MountVolume.SetUp failed for volume "secret" : secret "missing-volume-secret" not found
  ```
- **Verified**: `kubectl get secret missing-volume-secret -n siclaw-eval-yye-20260602` returns `NotFound`.
- **Pod spec**: Volume `secret` is declared with `secretName: missing-volume-secret` and `optional: false`.

### Impact / Scope

- Only this pod is affected.
- The pod will remain stuck indefinitely with no progress — the secret is mandatory (not optional) so the kubelet will keep retrying the mount every ~2 minutes.

### Confidence

**High** — the events and pod spec are unambiguous.

### Safe Remediation (read-only suggestion)

**Option A — Create the missing Secret** (preferred):
```bash
kubectl create secret generic missing-volume-secret \
  -n siclaw-eval-yye-20260602 \
  --from-literal=key=value
```
The pod will then bind the volume and start automatically.

**Option B — Remove the broken volume reference** (if the secret mount is not needed):
Edit the Pod (or its owner — Deployment/Job/etc.) to drop the `secret` volume and its corresponding `volumeMount` from the trainer container.

**Option C — Make the volume optional** (if the secret data is optional):
Set `optional: true` on the `secret` volume in the pod spec — the kubelet will then skip the mount and start the container.
