## Diagnosis for pod `c007-image` (Case c007)

### Root Cause

**Invalid image reference** — the pod is configured with:

```
registry.invalid/scitix/dcgm-exporter:v0
```

The registry hostname `registry.invalid` is a **reserved TLD that does not exist** (per RFC 2606). The container runtime cannot resolve or pull from this registry, resulting in `ImagePullBackOff`.

### Evidence

- Pod `c007-image` is in `ImagePullBackOff` status on node `cpu-10-208-55-85`.  
- Events show: `Back-off pulling image "registry.invalid/scitix/dcgm-exporter:v0"`.  
- The image spec uses the `.invalid` TLD, which is unresolvable by design.

### Impact / Scope

- **Single pod affected** — the workload never starts; container runtime cannot even attempt the pull.
- Only this pod is affected; other workloads in the namespace are presumably unaffected.

### Confidence

**High** — the event message and image spec directly confirm the diagnosis. This is not a transient or resource-related issue.

### Remediation

1. **Correct the image reference** to a valid registry (e.g. the real Docker Hub, a private registry reachable from the cluster, or a public image path).
2. After updating the image, the pod will automatically restart its pull attempt. If the reference is corrected, the pod should start normally.

Suggested patch approach (safe, read-only here — actionable by user):
```bash
kubectl set image pod/c007-image main=<correct-image> -n siclaw-eval-yye-20260602
```
Or edit the Deployment/Job/StatefulSet that owns this pod.
