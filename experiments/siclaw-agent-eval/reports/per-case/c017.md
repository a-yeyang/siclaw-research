## Diagnosis: Pod c017-crash

### Root Cause

The pod's container command is hardcoded to fail on purpose:

```
Command:
  sh -c "echo 'permission denied: /models'; exit 13"
```

The **container entrypoint explicitly exits with code 13** after printing "permission denied: /models". This is the *configured* command, not a runtime error — the pod was intentionally deployed to crash.

### Evidence

| Source | Detail |
|---|---|
| **Pod command** | `sh -c "echo 'permission denied: /models'; exit 13"` |
| **Exit code** | `13` (terminated with Reason: `Error`) |
| **Container logs** | `permission denied: /models` |
| **Restart count** | 182 over ~15h — each run lasts < 1 second |
| **Image** | `busybox:1.36` (pulled successfully, nothing wrong with the image) |

### Impact

- Pod is in `CrashLoopBackOff` and never becomes `Ready`.
- 0/1 containers ready — no work is performed.
- No volume mounts for `/models` exist, so this is not a real filesystem permission issue; the command is simulating one.

### Confidence

**High (100%)** — the pod's configured `command` field is the definitive source of behavior.

### Remediation

The pod's container command must be corrected. Suggested safe fix:

```yaml
# Replace the command with the actual training entrypoint
command:
  - /path/to/real/trainer
args:
  - --model-dir
  - /models
```

Or, if `/models` was meant to be mounted and exists on the node, add a volume + volumeMount:

```yaml
volumes:
  - name: models
    hostPath:
      path: /path/to/models
      type: Directory
containers:
  - volumeMounts:
      - name: models
        mountPath: /models
```

Either way, the current `command` line needs to be replaced with the real training binary — it's currently a placeholder that immediately exits with an error.
